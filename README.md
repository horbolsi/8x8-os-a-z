## One account, one 8x8 ID, one capability fabric

The public 8x8 experience is designed as an All-in-One platform spanning and interconnecting major capability families that are usually fragmented across many services:

- **Identity / Accounts / Profiles** — 8x8 ID, profiles, permissions, sessions, privacy, notifications and user workspaces.
- **AI / Agents / Connectors** — user-owned AI/model/API accounts, agents, automation and supported connectors under explicit tenant permission.
- **8x8 Terminal / Build Workspace** — isolated terminal, project workspace, coding/build tools, AI assistance, storage, previews, testing and supported deployment integrations.
- **Studio / Creator Tools** — research, writing, image, audio, video, music, multilingual production, editing and publishing workflows.
- **Social / Communities / Messaging** — feeds, posts, follows, groups, communities, messaging and creator channels as released.
- **Live / Streaming / TV / Radio** — live experiences, public channels, streaming, radio and future media-edge participation.
- **Gaming / Experiences** — games, achievements, community experiences and XM8-related product functions as released.
- **8x8 Wallet / Network / 8x8Scan** — public wallet and identity experiences, network information, explorer functions and interoperability with supported external networks.
- **8x8 Economy** — 8x8 plus approved token identities, subscriptions, fee policy, public economic receipts and future value-bearing functions only when separately production-gated.
- **NFT Vaults / Marketplace** — Vault discovery, lineage, verification, marketplace and visual-display functions as released.
- **Markets / Trading Intelligence** — public analytics, simulations, paper trading and separately gated value-bearing execution.
- **Governance / Contributions** — proposals, voting, community submissions, public decisions and future reward eligibility under separately ratified policy.
- **Transparency / Benchmarks / Evidence** — public receipts, treasury/liquidity/fee/subscription flows, network/proof metrics, benchmarks and evidence-bound status.
- **Nodes / Proof Fabric** — opt-in user devices/resources may participate through role-scoped node leases and verifiable receipts as supported.

## Proof + node participation

8x8 may support modular proof families including **PoW, PoS, Proof of Storage, Proof of Knowledge, Proof of Service** and future approved proof types.

Users may opt in their own devices, compute, storage or other supported resources as role-scoped nodes. User storage remains tenant-isolated and explicitly mounted into that user's workspace. A public node never receives OWNER_ROOT filesystem or private One-Fabric authority.

Economic rewards, staking, mining/resource rewards and token/coin/NFT issuance are **not implied by source code or a node receipt**. They become active only after the applicable security, anti-Sybil/fraud, legal/economic, native-network and treasury/issuance gates are proven.

## Radical transparency without exposing the sovereign engine

Public transparency can show verified economic and network evidence such as:

`fees → treasury → liquidity → rewards → operations`

with public role/address identifiers, asset/network, amount, timestamp, policy version, transaction/provider receipt, finality and verification state.

Transparency does **not** publish private signing keys, custody secrets, customer private identity, private infrastructure topology or proprietary OWNER_ROOT implementation.
